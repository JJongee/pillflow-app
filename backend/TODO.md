## 남은 작업

### 1. 입력이 생겨야 할 수 있는 것

지금은 참고 정보로만 보여 주고 판정(`verdict`)에 넣지 않습니다. 아래 입력이 생기면 판정으로 올릴 수 있습니다.

| 항목 | 필요한 입력 | 누가 |
|---|---|---|
| 임부금기 | 프로필에 임신 여부 | 서버(칸 추가) + 앱(입력 화면) |
| 용량주의 | ~~시간표에 숫자 용량과 단위~~ → 10/10 서버에 `dose_amount`·`dose_unit` 추가 완료. 이제 **김서현의 성분량 검증과 최대량 숫자화**를 기다립니다 | 김서현 |
| 투여기간주의 | 복용 시작일, 연속 복용 여부 | 서버 + 앱 |
| 노인주의 | 기준에 나이 값이 없어 판정 불가. 몇 세부터인지 팀이 정해야 함 | 팀 합의 |
| 효능군중복주의 | 적용 계열·예외·사용기간 규칙 (효능군 이름이 같다고 중복이 아님) | 김서현 + 팀 합의 |

### 2. 앱 화면 쪽 (서버는 그대로)

- 참고 정보 약품별 묶기 + 유형별 접기·펼치기 (손채은 10/9 제안, 10/8 고연수 1차 반영).
  접힌 상태에서도 주의 유형과 '기준 확인됨/확인 중'은 보이게 합니다. 응답의 `cautions[].item_seqs`로 묶을 수 있고, 서버는 보낸 약 순서대로 돌려줍니다.
- ~~1회 복용량 입력(숫자 + 단위)~~ → 10/10 서버 완료. `dose_amount`(숫자) + `dose_unit`(정·캡슐·포·mL·방울·매 6개, 앱 목록과 동일). `dose_text`도 그대로 남아 있고 둘 다 생략 가능합니다.
- 상태 문구를 '기준 연결 확인'으로 할지 '기준 확인됨'으로 할지 (손채은·고연수). 서버는 `status`로 `CONFIRMED`·`PENDING`·`CONFLICT`만 보내고 화면 문구는 앱이 정합니다.
- 오늘 복용 화면에서 같은 시각의 약을 하나로 묶기 (손채은 10/9 제안). 묶은 뒤에도 약별로 먹었어요·건너뛰기를 따로 처리합니다.
  `GET /me/intakes?date=`는 이미 시간 순서대로 돌려주고 줄마다 `time`과 `schedule_id`가 있어 앱에서 묶을 수 있습니다. 기록은 지금처럼 `PUT /me/intakes`에 `schedule_id` 하나씩 보내면 됩니다. **서버 변경 없음.**

### 3. 팀이 정해야 하는 것

- 자동 시간표의 기준 시각 기본값 5개와, 사용자가 바꾸는 화면 (손채은·고연수)
- 식간을 `EMPTY`로 묶을지, 값을 따로 둘지 (고연수)
- 용법 원문을 제안 화면에 어떻게 보여 줄지 (손채은)
- 용법 문장을 미리 정리해 DB에 넣을지, 서버가 그때그때 읽을지 (김서현)

### 4. 용량 초과 자동 판정 (10/10 김서현과 합의)

1단계에서는 **보류**합니다. 서버는 입력 구조와 점검까지만 갖춰 뒀습니다.

**10/10 김서현 1차 진행 결과**
- 함량 환산 검증: 1품목 → **20품목**(정 16·캡슐 4). 개인별 적정 용량 검증을 뜻하지는 않습니다.
- 최대량 구조화 후보: `dur_dose_limit_candidates`에 **1건**. 기준 1820의 4000 mg/day, adult. 대조 범위는 품목 **199302514 하나뿐**이며, **다른 19품목에 공통 적용하면 안 됩니다.**
- `automatic_decision_ready=false` 유지. 기존 용량 초과 판정 함수도 1품목 지원 그대로입니다.
- 그래서 서버는 이번 변경으로 동작이 달라지지 않습니다. 자동 판정은 계속 보류합니다.

그 뒤 결과와 지원 가능한 품목 범위를 더 받은 뒤에 서버 판정을 붙입니다. 그때 필요한 것
- 하루 합계: 같은 약의 시간표를 모두 더하기
- 성분 합계: 같은 성분을 가진 다른 약까지 더하기 (복합제 1,698건)
- 지원 범위 밖인 약은 "확인 중"으로 두고 '괜찮음'으로 표시하지 않기

### 5. 데이터가 더 오면 할 수 있는 것

- ~~노인주의 원문에 주의 내용과 비고가 비어 있는 건~~ → 10/9 김서현 확인 완료. DUR 원본부터 비어 있고 저장 과정 누락이 아닙니다. 전체 1,979건 중 58건에는 주의 내용이 있지만 앱 대상 521건에는 들어 있지 않습니다. 서버는 "원본에 상세 주의내용이 제공되지 않았어요."로 알려 줍니다.
- 투여기간주의 중 조건부 기간("무배란증:12일, 난포과자극유도:20일")은 숫자를 임의로 고르지 않고 원문 그대로 둡니다.

## 서버를 이어받는 사람에게

- DB는 김서현 백업을 복원해서 씁니다. 서버가 만드는 표는 `users`, `user_drugs`, `schedules`, `intake_logs` 4개뿐이고, 김서현 표는 읽기만 합니다.
- 새 백업을 받으면 기존 DB는 지우지 말고 이름을 바꿔 보관하세요. (`pillflow_v1`, `pillflow_v2`, `pillflow_v3`)
- 응답 형식을 바꿀 때는 **기존 칸을 고치지 말고 새 칸을 추가**하세요. 앱이 모르는 칸은 무시하므로 앱이 깨지지 않습니다.
- 기능을 추가하면 `check_api.py`에 점검을 같이 추가하고, `README.md`와 `API_CHANGES.md`도 고치세요.
- 기준을 확인하지 못한 데이터(`PENDING`)를 "문제 없음"으로 처리하지 마세요. "기준 확인 중"으로 그대로 보여 줘야 합니다.
